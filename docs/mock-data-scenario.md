# 목업 데이터 시나리오

이 문서는 현재 프론트엔드에서 사용하는 가짜 데이터를 프로젝트별로 정리한 문서입니다. 백엔드 API 연동 전까지 화면 흐름, 권한, 검증 결과, 조치 요청, 보고서 상태를 설명하기 위한 기준 자료입니다.

## 공통 전제

- 시스템은 건설 현장의 산업안전보건관리비 정산 프로젝트를 관리합니다.
- 사용자는 `프로젝트 담당자`와 `SHE 담당자`로 나뉩니다.
- 프로젝트 담당자는 담당 프로젝트를 확인하고 증빙자료를 업로드합니다.
- SHE 담당자는 전체 프로젝트를 확인하고 검증 결과를 바탕으로 조치 요청과 최종 확정을 수행합니다.
- 현재 데이터는 모두 프론트엔드 목업 데이터이며 실제 서버 데이터가 아닙니다.

## 공통 증빙자료 유형

- `usage_statement`: 사용내역서
- `receipt`: 영수증
- `site_photo`: 현장사진
- `tax_invoice`: 세금내역서 + 제3자사실관계확인서
- `other_document`: 기타 서류

### 검증 시나리오

광명 프로젝트는 초기 업로드 대기 시나리오입니다.

주요 판단:

- 이번 차수 자료가 아직 업로드되지 않았습니다.
- 검증 결과는 아직 생성되지 않았습니다.
- 프로젝트 담당자가 자료를 제출하면 아카이브 분류가 시작되고, 이후 SHE 담당자가 검증을 수행합니다.

예상 검증 흐름:

1. 프로젝트 담당자가 증빙 업로드 탭에서 자료를 제출합니다.
2. 자료가 9개 산안비 항목으로 자동 분류됩니다.
3. 아카이브에서 분류 결과를 확인합니다.
4. SHE 담당자가 유효성 검증 탭에서 OCR, 비전, 법령 검증을 진행합니다.
5. 문제가 없으면 보고서 작성 상태로 이동합니다.
6. 문제가 있으면 SHE 담당자가 조치 요청을 수행합니다.

### 화면 흐름

프로젝트 담당자:

1. 담당 프로젝트 목록에서 광명 프로젝트를 선택합니다.
2. 개요에서 프로젝트가 업로드 대기 상태임을 확인합니다.
3. 증빙 업로드 탭에서 이번 차수 자료를 제출합니다.
4. 아카이브에서 자동 분류 결과를 확인합니다.

SHE 담당자:

1. 대시보드에서 업로드 대기 프로젝트를 확인합니다.
2. 광명 프로젝트 상세로 이동할 수 있습니다.
3. 아직 검증 결과가 없으므로 조치 요청은 생성하지 않습니다.
4. 프로젝트 담당자의 업로드 이후 검증 결과를 확인합니다.

## 정리

현재 목업 데이터는 세 가지 상태를 나눠 보여주기 위한 구조입니다.

- `동탄`은 문제가 발생한 조치 요청 프로젝트입니다.
- `평택`은 검증이 끝나 보고서 작성 상태로 넘어간 프로젝트입니다.
- `광명`은 아직 자료 업로드를 기다리는 초기 프로젝트입니다.

특히 동탄 프로젝트의 문제 상황은 안전모, 안전화, 안전벨트 사진 문제를 중심으로 설명합니다. 이 시나리오를 기준으로 증빙 업로드, 아카이브, 유효성 검증, 조치 요청, 보고서 흐름을 설명할 수 있습니다.
